# Experience Segmentation Refinement Plan

1. Ranked diagnosis
- `split_experience_entries()` is over-triggering on `_is_probable_entry_start()` because it does raw substring checks against `COMPANY_KEYWORDS`; short tokens like `co` and `inc` match inside ordinary prose (`recording`, `control`, `including`) and fracture a single job into many chunks.
- The same splitter treats any date-bearing line as a fresh entry start, so `role/company` and `date` lines are separated before `parse_experience_block()` can use `_match_multiline_header()` or `_match_role_company_line()` on the full header.
- The same splitter treats any all-caps line as a fresh entry start, so header/name residue such as `CURRICULUM VITAE` / `DIVYANK SINGH` can be emitted as standalone chunks before the first real job header.
- Once those coarse chunks are emitted, `parse_experience_block()` falls back to weak single-chunk parsing and produces fake entries (`Experience`, header residue, date-only entries) instead of one coherent experience item.

2. Exact current chunk-splitting logic inside `parse_experience_block(...)`
- `parse_experience_block()` first returns early for an experience-shaped markdown table; otherwise if any markdown table exists it returns one text fallback entry.
- On plain text it calls `split_experience_entries(block)`; if that returns nothing, it uses `[block.splitlines()]`.
- `split_experience_entries()` walks `block.splitlines()` and:
  - flushes the current chunk on blank lines,
  - hard-stops on `driving license` / `licenses` lines,
  - hard-stops on detected non-experience section headings in `SECTION_TERMINATORS`,
  - otherwise flushes before the current line when `_is_probable_entry_start(line, current)` is true.
- `_is_probable_entry_start()` returns true only when `current` is non-empty and the stripped line matches any of:
  - `any(keyword in lower for keyword in COMPANY_KEYWORDS)`
  - `any(keyword in lower for keyword in POSITION_KEYWORDS)`
  - `stripped.isupper()`
  - `re.search(DATE_PATTERN, stripped)`

## Follow-up Slice: Experience Matrix Row Alignment

1. Ranked diagnosis
- The clean markdown-table path is already working on the in-repo Prasanna repro block; the remaining failure is the coarse OCR/text block seen on `fixtures/cv (308).pdf`, where the experience matrix reaches `parse_experience_block(...)` with `0` markdown tables.
