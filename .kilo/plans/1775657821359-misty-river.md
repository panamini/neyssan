## Findings From Audit

### 1. Additional Information / Custom / Projects still have split rendering behavior
- `applyImportRecoveryItems()` already materializes `additional_information` and `custom` into block-backed `text` sections via `applyToPlainBlocks()`.
- The user-visible failure is not section creation; it is rendering inconsistency.
- `SectionEditor` now has a `sectionType === "text"` branch, but other active paths still retain legacy `section.content` assumptions and generic block previews only surface titles in some contexts.
- `projects` is worse: recovery targets can land in a `projects` section, but `SectionEditor` has no dedicated `projects` branch, so it falls through to the old generic editor path that still prefers `section.content` over `blocks`.

### 2. Summary / Experience / Education do not expose fallback text clearly
- `profile` now surfaces recovery-only text through a visible recovered-note UI.
- `summary` still merges fallback text directly into `summaryItem.summary` and does not surface the recovery provenance separately.
- `experience` and `education` currently coerce fallback text into typed fields too aggressively:
  - `applyToExperience()` derives title/position/company from raw text and also writes the full text into `responsibilities`.
  - `applyToEducation()` derives `degree` from the raw text and also writes the full text into `description`.
- This explains the reported "text appears dumped into job role + responsibilities" behavior.
- The typed modals (`SummaryModal`, `ExperienceModal`, `EducationModal`) do not read/display `importRecovery` block metadata today.

### 3. Recovery re-entry is only guaranteed while a session is pending
- Current banner/toolbar/panel re-entry is driven by `pendingRecoveryImport`, draft session, metadata session, or active import signals.
- After a fully-applied review with no remaining pending session, the re-entry controls disappear because the recovery session is deleted.
- The imported blocks still persist `attributes.importRecovery`, so the data provenance survives, but the reopenable workspace does not.

### 4. The scroll jump root cause is already narrowed
- The main jump source is the recovery auto-scroll effect in `ProfileReviewCard`, which must fire only on closed->open transitions, not on every in-place recovery item mutation.
- A second-pass audit should still verify no other scroll/focus behavior in `ImportRecoveryPanel` runs on fragment commit (`selectedFragmentId` scroll sync, button focus changes, or browser selection reset).

### 5. Affiliation styling is a cosmetic mismatch, not a trust blocker
- Current `Affiliations` rendering uses its own card/list styling and is functionally correct.
- This should remain out of scope unless a low-risk CSS-only harmonization falls out naturally.

## Implementation Plan

### A. Unify text-backed recovery rendering once and mark legacy paths explicitly
1. In `SectionEditor`, make block-backed rendering the authoritative path for active `text` sections and document `section.content` handling as legacy fallback only.
2. Add a small helper comment block near the generic editor fallback stating:
   - active editor sections should be block-backed
   - `section.content` exists only for legacy hydration / migration compatibility
3. Audit other active renderers that still prefer `section.content` for editor-visible text and switch them to blocks where safe.
4. Apply this to:
   - `Additional Information`
   - custom `Add your own`
   - any other `type: "text"` recovery targets

### B. Fix Additional Information and custom text sections end-to-end
1. Verify `additional_information` and `custom` still materialize through `applyToPlainBlocks()`.
2. Ensure their active renderer surfaces block body text, not just block titles.
3. Add/update tests proving reviewed text for:
   - `Additional Information`
   - a named custom target
   appears after save and render.

### C. Fix Projects recovery output visibility
1. Audit whether `projects` should be treated as block-backed plain text in the current editor or already has a typed renderer elsewhere.
2. Minimal fix recommendation:
   - add a `projects` branch in `SectionEditor` that renders existing blocks using the same visible pattern as plain text / non-typed sections.
3. Add a regression test for recovery-created `Projects` content becoming visible.

### D. Make structured fallback text deterministic and visibly separate
1. Add a shared helper in `SectionEditor` (or nearby utility) to collect `importRecovery` block text linked to a structured section/item and render it as `Recovered note` UI.
2. Extend the existing pattern used for `Profile` to:
   - `Summary`
   - `Experience`
   - `Education`
   - keep `Certifications` support already added
3. For `Summary`:
   - stop relying only on merged summary text for trust
   - show the fallback note in both preview/body and, if possible cheaply, in `SummaryModal`
4. For `Experience` / `Education`:
   - tighten `applyToExperience()` / `applyToEducation()` so typed field extraction is conservative
   - only fill headline fields when parsing confidence is clear enough from the text structure
   - otherwise store the text as a linked recovery note block and render it visibly as a note instead of shoving it into `position` / `degree`
5. Keep the implementation deterministic; no AI or secondary review layer.

### E. Keep recovery re-entry visible while it still matters
1. Keep the explicit banner recovery button added in `ImportWarningBanner`.
2. Keep toolbar + inline panel re-entry labels consistent with the active state:
   - `Open recovery workspace`
   - `Resume recovery review`
3. Preserve the completed recovery session snapshot until the next import or explicit dismissal so the user can re-open the same recovery workspace once more after save.

### F. Verify no jump after Add to section
1. Re-audit the `pendingRecoveryImport` auto-scroll effect in `ProfileReviewCard`.
2. Re-audit `ImportRecoveryPanel` for:
   - selection reset side effects
   - fragment scroll sync effects
   - any focus-stealing behavior after `commitSelection()`
3. Add a regression test if feasible at component level; otherwise document a manual verification script.

## Resolved Decision
- Post-save recovery should remain reopenable for the same import cycle.
- Implementation default: preserve the completed recovery session until the next import or explicit dismissal.
