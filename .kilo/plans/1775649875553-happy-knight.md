## Root causes by issue

### 1. Import save pipeline / destination visibility

- Recovery commit path is active: `ImportRecoveryPanel` -> `ProfileReviewCard.applyReviewedRecoveryImport()` -> `applyImportRecoveryItems(...)` -> `importCv(...)`.
- Data-layer persistence for fragments exists, but trust is weak because users do not get a strong destination reveal after save.
- `hobbies` and `affiliations` are currently plain title-backed `text` sections, so imported content may persist but remain hard to find.
- `certifications` currently persists as an untyped plain section (`structuredContent: null`), so there is no dedicated semantic editor/renderer to make saved content feel trustworthy.
- `contact` is duplicated as both profile-owned structured data and a standalone recovery/add target, which creates ambiguity and weakens visible outcomes.

### 2. Recovery entry points / review surface

- `Review import changes` currently multiplexes parser review and recovery resume.
- Inline `Import review` checks can open, but they do not expose a strong recovery CTA and do not provide an explicit close affordance.
- Warning banner auto-hide is separate and already exists; the confusion comes from the inline review panel, not the banner.

### 3. Recovery interaction friction

- Non-highlighted text selection is technically supported and should stay that way.
- Mixed-content extraction is offset-safe but semantically heuristic, so the UI needs small trust copy rather than more system complexity.
- `Ignore` already means “ignore remaining residue only,” but that meaning is not obvious enough.
- Chip/highlight sync exists through local fragment selection state, but first-click feedback is not deterministic enough.

### 4. Typed experience / education modal regression

- `SectionEditor` opens experience/education modals locally, but modal rendering is gated by document-wide `isV1Active`.
- `isV1Active` in `CvLibraryContext` is too strict: any extra/noncanonical section flips it false and prevents typed modal mount.
- The `openTypedModal` inspector hint path looks incomplete and may further obscure expected edit behavior.

### 5. Section semantic/model mismatch

- `contact` should be profile-owned, not independently addable/recoverable.
- `hobbies` is semantically a tag/list section and should reuse the `skills`-style model and modal UX.
- `certifications` already has its own section type and should become a real lightweight typed section.
- `affiliations` is currently plain text-backed, but the requested semantics justify a lightweight structured model and modal while keeping section architecture lean.

## Section decisions for implementation

### Contact

- Decision: treat `contact` as legacy-compatible but no longer addable/manageable/recoverable.
- Implementation rule:
  - remove `contact` from add/manage lists and recovery target options;
  - route recovered contact-like text into `profile` instead of creating a `contact` section;
  - keep legacy schema compatibility for existing saved CVs in this sprint.

### Hobbies

- Decision: keep hobbies as a title-backed `text` section for minimal architectural change, but reuse the `skills`-style data model and modal UX.
- Lean path:
  - store hobbies as `ISkillItem[]`-compatible structured content under a `text` section titled `Hobbies`;
  - reuse `SkillsModal` and similar inline chip rendering in `SectionEditor` based on section title;
  - tune suggestion labels/copy to hobby-oriented language.

### Certifications

- Decision: promote certifications from plain blocks to a dedicated lightweight typed section on the existing `certifications` section type.
- Required additions:
  - `ICertificationItem` type + schema + factory;
  - lightweight certification modal;
  - recovery materialization into typed `structuredContent` plus representative blocks.

### Affiliations

- Decision: keep affiliations as a title-backed `text` section for section-level compatibility, but add a lightweight structured modal/data model.
- Required additions:
  - `IAffiliationItem` type + schema + factory;
  - lightweight modal;
  - `SectionEditor` title-based branch for `Affiliations`.

## Implementation phases

### Phase 1 — Verify/fix import save pipeline and visible destination trust

1. Audit and lock the actual save path.
   - Trace `ImportRecoveryPanel` payloads through `ProfileReviewCard` commit state into `applyImportRecoveryItems(...)` and `importCv(...)`.
   - Confirm both fragment text and accepted residue reach destination `blocks`/`structuredContent`, not only metadata.

2. Fix destination materialization mismatches.
   - Remove recovery creation of standalone `contact` sections and map that content into `profile`.
   - Confirm `hobbies` materialization survives import normalization and is visible as real content.
   - Convert `certifications` materialization from plain-block-only behavior to typed item creation once the certification schema/modal lands.
   - Convert `affiliations` materialization from plain text blocks to structured item creation once the affiliation schema/modal lands.

3. Add lightweight destination visibility after save.
   - Expand affected/new destination sections after import when safe.
   - Add subtle post-save reveal state for touched sections or blocks instead of aggressive scroll-only behavior.
   - Prefer a small focus/reveal/highlight token in existing styling systems.

4. Ensure text-backed destinations are visibly discoverable.
   - `Hobbies` must clearly show imported content immediately after save.
   - If a section is newly created, it should not remain visually buried.

### Phase 2 — Repair recovery entry points and review surface behavior

1. Keep `Review import changes` visible whenever parser checks or recovery state exist.
2. Make the action deterministic.
   - active/pending recovery -> resume/open recovery and surface it clearly;
   - otherwise -> open parser/import checks.
3. Add explicit close/toggle affordance to inline `Import review`.
4. Keep warning banner auto-hide behavior separate from the inline review panel.
5. Add a visible recovery resume affordance near inline review when recovery is pending, not only in the toolbar.

### Phase 3 — Reduce recovery interaction friction

1. Preserve free selection of non-highlighted text.
2. Add lightweight helper copy near drawer preview:
   - `Tip: Extract coherent phrases/sentences for best results.`
3. Clarify residue behavior inline:
   - `Ignore` affects only remaining unassigned text;
   - already saved fragments remain included.
4. Make chip/highlight linking deterministic.
   - first click selects immediately;
   - selected chip reveals the corresponding text;
   - selected highlight and chip remain in sync.
5. Do not add onboarding/tutorial systems.

### Phase 4 — Fix typed experience/education modal regression

1. Remove the overly strict document-wide dependency from typed modal rendering.
2. Gate typed modal mount/open behavior on local section type and local structured expectations instead.
3. Audit `openTypedModal` handoff and either wire it correctly or stop it from swallowing edit intent.

### Phase 5 — Section modal/data alignment

1. Extend schema/types minimally.
   - add `ICertificationItem`.
   - add `IAffiliationItem`.
   - keep hobbies on reused `ISkillItem[]` shape.

2. Update factories/templates/normalization.
   - `cv-template.ts`
   - `cvDocument` types
   - `cvDocument.schema.ts`
   - any normalization/representative-block helpers needed for typed save safety.

3. Reuse nearest editor patterns.
   - `Hobbies` -> reuse `SkillsModal` pattern and chip/list rendering.
   - `Certifications` -> new lightweight modal closer to achievements than education.
   - `Affiliations` -> new lightweight modal, possibly sharing shell/field utilities with certifications.

4. Update recovery/add/manage exposure only after mapping is ready.
   - do not expose a new typed destination before parser/materialization and rendering support exist.
