# Import Recovery UX Refinement Sprint

## Goal

Refine the current Lean Recovery MVP without changing the architecture.

Focus on:

- trust
- clarity
- reliable selection behavior
- obvious recovery re-entry
- clearer save outcomes

Keep this pass lean. No new frameworks, no modal chains, no structured draft engine.

## Architecture Fit

- `my-app/src/components/ImportRecoveryPanel.tsx`
  - owns selection UI, drawer behavior, highlight rendering, keyboard shortcuts
- `my-app/src/components/ProfileReviewCard.tsx`
  - owns recovery session state, resume logic, toolbar entry point, save/apply flow
- `my-app/src/lib/import-recovery.ts`
  - owns overlap detection, remaining-text calculation, fragment application
- `my-app/src/contexts/CvLibraryContext.tsx`
  - remains the final persistence gate through `importCv(...)`
- `my-app/src/styles/product.css`
  - must supply all styling changes using existing token families
- `my-app/src/lib/icons.tsx`
  - must supply any help/tooltip icon additions

## Constraints

Do not add:

- state machine framework
- generic tooltip framework
- mapping/confirmation modals
- structured draft engine
- per-card commit model
- new persistence architecture
- broad refactors beyond what is needed for these fixes

Reuse existing design tokens and tooltip/icon patterns only.

## Risks

### Highest risk

1. Offset fixes may break selection or fragment rendering if measurable text and decorative controls are not separated cleanly.
2. Persistent toolbar trigger may accidentally blur parser-warning review and recovery review if routing is not explicit.
3. Footer summary can reduce trust if it does not match actual save behavior exactly.
4. Two-step removal can reintroduce offset bugs if the remove affordance leaks back into measurable text flow.
5. Residue cleanup can become too aggressive if heuristics are broad.

## Regression Focus

- first-fragment and second-fragment highlight alignment
- reselection replacing draft without clearing committed fragments
- no outside-click auto-commit
- toolbar trigger still visible after save when recovery is resumable
- trigger routes correctly between parser review and recovery review
- footer summary matches real saved/pending counts
- two-step fragment removal works without corrupting offsets
- residue cleanup skips junk only, not meaningful text
